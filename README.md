# Spaceholder

Spaceholder 是一个浏览器本地运行的键盘区域映射音乐游戏与手工制谱器原型。项目使用 React + Vite + TypeScript，不依赖后端，音频、曲绘和谱面都由用户在浏览器本地导入。

当前项目主线面向键盘玩法。触摸版应作为独立分支开发，优先复用谱面数据结构、渲染和判定核心，在输入层增加触摸适配。

## 运行与部署

```bash
npm install
npm run dev
npm run build
```

Vercel 部署使用：

- Build Command: `npm run build`
- Output Directory: `dist`
- SPA fallback 已在 `vercel.json` 配置

页面入口：

- `/`：游玩临时主界面
- `/play`：游玩临时主界面
- `/editor`：独立制谱器

默认 Vercel 域名形如 `https://项目名.vercel.app`。游玩页可访问 `/` 或 `/play`，制谱器访问 `/editor`。

## 页面结构

### Play 主界面

Play 页面进入后先显示临时主界面，包含：

- `Import Audio`：导入本地音频
- `Upload Artwork`：导入曲绘
- `Import JSON`：导入谱面 JSON
- `Settings`：游玩设置
- `Play`：进入正式游玩界面

Play 主界面导入的音频和曲绘只服务于当前游玩会话。JSON 导入会更新当前谱面；若 JSON 不带音频或曲绘，可继续手动导入覆盖。

### 正式游玩界面

正式游玩界面专注谱面显示：

- 全屏轨道画布
- 右上角歌曲信息、曲绘和分数
- 中上方 combo
- 下方判定线和淡化键位提示
- 左上角 `Pause`

正式游玩界面不再显示 Settings，也没有进入 Editor 的入口。

暂停方式：

- 点击左上角 `Pause`
- 按 `Esc`

暂停菜单：

- `Resume`：继续
- `Restart`：从头重开
- `Menu`：停止并回到 Play 主界面

### Editor 页面

Editor 独立位于 `/editor`，不提供进入 Play 的按钮。它保留：

- 导入音频
- 导入曲绘
- 导入 JSON
- Save 更新 JSON
- 手工铺谱工具
- 音乐预览
- 时间组编辑

Editor 的预览只用于制谱校对，不承担正式游玩入口。

## 玩法与按键分配

谱面以键盘横向区域为核心。当前只支持偶数普通轨道：

- 最小 `2K`
- 最大 `10K`
- 默认 `4K`
- 谱面最大轨道数由 Editor 的“普通轨道”决定
- 初始轨道数由“初始轨道”决定

当前 4K 中心键位为：

```text
F G H J
```

更多轨道以键盘横向位置展开，整体围绕键盘中心布局。轨道数量变化目前由独立 `lane` note 触发，播放时按当前轨道数显示，但谱面数据仍按最大轨道写谱。

控制键不参与普通判定，例如：

- Esc
- Tab
- Shift
- Ctrl
- Alt
- 方向键

Space 类输入被分为左右两类：

- L Space：蓝色，只能用 `V` 及其左侧字母键接
- R Space：红色，只能用 `N` 及其右侧字母和符号键接
- Space Hold：黄色，保持原有空格类长条逻辑

普通 Tap / Tap Hold 使用对应轨道键判定。

## Note 类型

当前谱面中重要 note 形态：

### Tap

- 白色
- 单点音符
- 显示时底部对齐时间线/小节线
- 在游玩中到达判定线附近按对应轨道键判定

### Tap Hold

- 白色长条，整体比 Tap 略深，头部为接触判定线的一端
- 放置时通过两次点击确定起点和终点
- 有 `holdDensity` 物量
- 物量不放在开头或结尾：
  - 1 物量：默认中间，也可选头/中/尾
  - 2 物量：三等分点
  - 更多物量：均匀分布于长条内部
- 头物量到达时按住并持续到后续物量，可保持判定
- 两个物量之间松手不会立刻断，只要下一个物量到达前接回即可
- 漏过物量后不能追回

### L Space / R Space

- L Space 蓝色，R Space 红色
- 本质是横跨多个轨道的 Space 类单点音符
- 编辑器中由 `Add L`、`Add R` 放置
- 菜单参数中的 `跨度` 控制覆盖轨道数
- 可以部分超界或完全超界
- 完全超界 Space 显示为淡色，不参与判定
- 若轨道变化使原本超界的 Space 进入可判定范围，则正常参与判定

### Space Hold

- 黄色长条
- 保留原有空格类长条表现
- 时间长度按吸附线确定头尾，允许短于 100ms
- 只要检测到空格/Space 类输入处于按下状态，到达判定线时即可判定
- 可以拆分内部物量并移动到不同轨道
- 同一轨道上时间相连的单物量 Space Hold 可组合成较长 Space Hold

### Lane

- 不可判定
- 表现为与判定线类似材质的一根横线
- 下落到判定线时，把当前显示轨道数切换为指定数量
- 线宽等于即将切换到的轨道数量宽度，居中显示
- 可以在编辑器中被选中，并与其他音符一起移动
- Timing Group 只影响 Lane 的视觉，不影响实际触发时间

## 判定与计分

判定结果：

- `great`
- `good`
- `bad`
- `miss`

判定核心：

- Tap / Space 在判定窗口内按下对应输入后判定
- Hold 按内部物量逐个判定
- Lane 不计入判定
- 完全超界 Space 不计入判定和分数
- 未判定 note 不计 combo，不加分

分数：

- 满分 `10,000,000`
- 所有可计分物量均分总分
- `great` 得全分
- `good` 得一半分
- `bad` 和 `miss` 不得分
- 分数显示使用 0 补齐位数

Key 音：

- 谱面 key 音按 note 时间或 hold 物量时间调度播放
- 不由玩家真实按键时间决定
- `good` 只影响判定，不影响 key 音调度
- miss 不应补播 key 音
- Editor 放置音符时的声音只是即时 UI 反馈

谱面偏移：

- 设置项为 `Chart Offset`
- 代表谱面与音乐的距离
- 负数：谱面更早开始
- 正数：谱面更晚开始

## 编辑器设计

Editor 是竖向手工制谱器，但视觉尽量接近游玩界面：

- 判定线固定在下方
- 音符从上向下落
- 鼠标滚轮自然滚动谱面时间
- 播放预览和当前时间线联动
- 小节线由 BPM 和吸附精度计算
- 改 BPM 只改变网格，不拉伸已有音符

制谱工具状态：

- 默认是选择指针状态
- 添加音符按钮重复点击可激活/熄灭
- 不能同时激活两种添加模式
- 选中音符后进入选择操作界面
- 选择内容被删除后直接返回默认状态

选择功能：

- 可选择单个音符
- 可用两次点击确定段落起点/终点
- 可删除、复制、镜像、移动段落
- 可横向/纵向移动选中内容
- 镜像仅限偶数轨道
- 镜像时 L/R Space 颜色也反转

放置细节：

- Tap / Tap Hold 宽度可通过 Note Width 调整，默认可占满轨道宽度
- Tap / Tap Hold 置于更高层级，重叠 L/R Space 或 Space Hold 时仍可见
- Space 类放置支持超界
- Space 类放置指针以中线为参考：
  - 鼠标在中线左边时，以预览 key 最右边控制放置
  - 鼠标在中线右边时，以预览 key 最左边控制放置
  - 中线区域允许居中放置，例如 4K 的 `G/H` 中间

保存：

- `Save` 更新已导入的 JSON 文件
- 没有可写文件句柄时回退为保存/下载
- 当前不保留单独 Export 按钮

## Timing Group

Timing Group 用于控制 note 的视觉下落演出，不改变实际谱面时间。

每个 note 可以绑定一个时间组。支持事件：

- `speed`：阶梯变速，`timeMs` 是开始变速时间，`multiplier` 是倍率
- `freeze`：卡顿，持续 `durationMs` 后瞬移追上
- `opacity`：透明度变化，可设置 `transitionMs`

重要规则：

- Timing Group 只影响视觉
- 不影响判定时间
- 不影响音乐播放时间
- 不影响 key 音时间
- 不影响 Lane 变轨触发时间

典型用途：

- 高速段
- 停顿演出
- 幽灵/淡入淡出音符

## 代码结构与规范

核心文件：

- `src/App.tsx`：页面、Play、Editor、判定、渲染、导入保存逻辑
- `src/types.ts`：谱面、note、判定、时间组等类型
- `src/lib/charting.ts`：谱面创建、BPM 网格、小节线、Timing Group 归一化
- `src/lib/keyboard.ts`：键盘映射、可用键、轨道配置
- `src/styles.css`：所有页面和音符样式

工程规范：

- React + TypeScript
- 优先保持现有数据结构兼容
- 不引入后端
- 不上传用户音频/曲绘
- 文件编辑应尽量集中、少做无关重构
- 新功能优先复用已有 note/判定/渲染 helper
- 构建验证使用 `npm run build`

触摸版开发建议：

- 不要让触摸直接模拟 DOM click
- 增加统一输入层，例如 `VirtualInput`
- 键盘和触摸都转换为同一类游戏输入事件
- 判定核心只接收“轨道/Space 类 pressed 状态”，不关心输入来源
- 触摸使用 `pointerdown`、`pointerup`、`pointercancel`
- 舞台设置 `touch-action: none` 和 `user-select: none`
- 支持多点触控，同一时间多个 pointerId 可按住不同区域
- 普通轨道触摸区应贴合判定线下方轨道宽度
- L/R Space 可用左右侧特殊触摸区或左右半区实现
- Space Hold 需要持续按住状态，而不是单次点击
- Editor 移动端建议后做，优先完成 Play 触摸判定

## 已知问题与注意事项

- 默认 `*.vercel.app` 国内访问不保证稳定
- Vite 构建会出现 `file-type` 依赖的 eval warning，目前不阻止部署
- 当前 README 描述的是键盘主线版本，触摸版应在独立分支中演进
- Play 主界面导入的音频/曲绘是浏览器会话内对象，不会自动写入 JSON
- 不同浏览器对 File System Access API 支持不同，Save 可能回退为下载
- 音频、曲绘、谱面均为本地导入，不上传服务器
- 当前项目仍有较多逻辑集中在 `App.tsx`，后续触摸版可先抽输入层，再逐步拆组件
